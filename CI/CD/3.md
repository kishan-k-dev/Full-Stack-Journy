# 3. YAML & GitHub Actions Workflow Configuration ⚙️

## 1. What is YAML?

YAML stands for **YAML Ain't Markup Language**.

It is a simple file format used to store configuration and instructions.

In simple words:

YAML tells a tool what to do and how to do it.

GitHub Actions uses YAML files to define workflows.

Example:

```yaml
name: My First Workflow
```

This defines the name of our workflow.

---

## 2. Basic YAML Syntax

YAML uses indentation (spaces) to organize information.

Example:

```yaml
student:
  name: Kishan
  skill: Python
  experience: Fresher
```

Here:
- `student` is the main section.
- `name`, `skill`, and `experience` are values.
- Indentation shows the relationship between them.

**Important YAML Rules:**

- Use spaces for indentation.
- Avoid using tabs.
- Use `key: value` format.
- Use `-` to create list items.
- Indentation must be consistent.

---

## 3. What is a GitHub Actions Workflow File?

A workflow file contains instructions that GitHub Actions follows.

Workflow files use the `.yml` or `.yaml` extension.

They must be stored inside:

```text
.github/workflows/
```

Example:

```text
MyProject/
    |
    |--- main.py
    |
    |--- .github/
           |
           |--- workflows/
                  |
                  |--- python.yml
```

---

## 4. Important Workflow Components

A basic GitHub Actions workflow contains these components:

| Component | Purpose |
|---|---|
| name | Workflow name |
| on | When workflow starts |
| jobs | Tasks to execute |
| runs-on | Machine used to run a job |
| steps | Individual tasks |
| uses | Uses an existing action |
| run | Executes a command |

---

## 5. Understanding a Workflow File

Example:

```yaml
name: Python CI

on:
  push:
    branches:
      - main

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Print Message
        run: echo "Hello from GitHub Actions"
```

### Explanation

**name: Python CI**

Defines the workflow name.

**on: push**

Runs the workflow when code is pushed.

**branches: main**

Runs when the push happens on the main branch.

**jobs:**

Defines the jobs in the workflow.

**test:**

This is the name of our job.

**runs-on: ubuntu-latest**

Runs the job on an Ubuntu machine.

**steps:**

Contains the tasks that the job performs.

**uses: actions/checkout@v4**

Downloads your repository code into the runner.

**run:**

Executes a terminal command.

---

## 6. What is the Difference Between `uses` and `run`?

| uses | run |
|---|---|
| Uses an existing GitHub Action | Executes a command |
| Reuses predefined functionality | Runs shell commands or scripts |
| Example: Checkout code | Example: Install Python |

Example:

```yaml
- name: Checkout Code
  uses: actions/checkout@v4

- name: Display Message
  run: echo "Welcome to CI/CD"
```

## 7. Create Your First GitHub Actions Workflow

Let's create a simple workflow.

### Step 1: Open Your GitHub Project

Open your existing GitHub repository.

### Step 2: Create a Folder

Create this folder structure in your project:

```text
.github/
    workflows/
```

### Step 3: Create a YAML File

Inside the `workflows` folder, create:

```text
hello.yml
```

### Step 4: Add This Code

```yaml
name: My First Workflow

on:
  push:
    branches:
      - main

jobs:
  hello:
    runs-on: ubuntu-latest

    steps:
      - name: Welcome Message
        run: echo "Hello Kishan! GitHub Actions is Working."
```

### Step 5: Push Your Code

Save the file and push it to GitHub.

### Step 6: Check the Result

1. Open your GitHub repository.
2. Click the Actions tab.
3. Open your workflow.
4. Check the execution result.

You should see the message:

```text
Hello Kishan! GitHub Actions is Working.
```

## 8. Common YAML Mistakes

### Mistake 1: Incorrect Indentation

Incorrect:

```yaml
jobs:
test:
  runs-on: ubuntu-latest
```

Correct:

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
```

### Mistake 2: Using Tabs

YAML expects spaces for indentation. Avoid tabs.

### Mistake 3: Incorrect File Location

Incorrect:

```text
MyProject/
    hello.yml
```

Correct:

```text
MyProject/
    .github/
        workflows/
            hello.yml
```

### Mistake 4: Wrong Branch Name

If your repository uses `main`, don't configure the workflow to trigger only on `master`.

## 9. Interview Questions & Answers

**Q1. What is YAML?**

YAML is a human-readable configuration format used to define settings and instructions.

**Q2. Why does GitHub Actions use YAML?**

It uses YAML to define workflows, jobs, triggers, and steps.

**Q3. Where are workflow files stored?**

Inside the `.github/workflows/` directory.

**Q4. What is the purpose of `runs-on`?**

It specifies the machine or runner environment used to execute a job.

**Q5. What is the difference between `uses` and `run`?**

`uses` runs an existing action, whereas `run` executes a command or script.

**Q6. What is `actions/checkout`?**

It is an action that checks out the repository code so the workflow can access it.

**Q7. What happens when we push code to GitHub?**

If the push matches a workflow trigger, GitHub Actions starts the configured workflow.

**Q8. What are `.yml` and `.yaml`?**

Both are file extensions used for YAML files.
