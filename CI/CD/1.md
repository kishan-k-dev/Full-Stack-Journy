
# 1. CI/CD Fundamentals 🚀

## 1. What is CI/CD?

CI/CD stands for:

- CI = Continuous Integration
- CD = Continuous Delivery
- CD = Continuous Deployment

CI/CD is a software development practice that automates testing, building, and releasing applications.

**Simple Example:**

Imagine you update your Python project and push the code to GitHub.

Instead of manually testing and deploying everything, CI/CD can automatically perform these tasks.

---

## 2. What is Continuous Integration (CI)?

Continuous Integration means regularly combining code changes from different developers into a shared repository.

Whenever new code is pushed to GitHub, automated checks can run.

### Example

```text
Developer writes code
        ↓
Push code to GitHub
        ↓
Automated tests run
        ↓
Check for errors
        ↓
Code is ready for next stage
```

**Why do we use CI?**

- Find errors early.
- Test code automatically.
- Avoid integration problems.
- Improve code quality.

---

## 3. What is Continuous Delivery?

Continuous Delivery means automatically building and testing an application so that it is always ready for release.

However, deploying to production may still require manual approval.

### Example

```text
Developer pushes code
        ↓
Automated testing
        ↓
Application build
        ↓
Ready for deployment
        ↓
Manual approval
        ↓
Production release
```

---

## 4. What is Continuous Deployment?

Continuous Deployment means automatically releasing code to production whenever it passes all required checks.

No manual approval is normally required for each release.

### Example

```text
Developer pushes code
        ↓
Automated testing
        ↓
Application build
        ↓
Automatic deployment
        ↓
Updated application
```

---

## 5. Continuous Delivery vs Continuous Deployment

| Continuous Delivery | Continuous Deployment |
|---|---|
| Application is ready for release | Application is automatically released |
| May require manual approval | Normally no manual approval |
| Deployment is controlled | Deployment is automated |

**Remember:**

Continuous Delivery = Ready to deploy.

Continuous Deployment = Automatically deployed.

---

## 6. How Does CI/CD Work in Real Projects?

Imagine you developed a Python FastAPI application.

You uploaded the project to GitHub.

Whenever you make changes:

```text
Write Python Code
       ↓
Push to GitHub
       ↓
CI/CD Pipeline Starts
       ↓
Run Automated Tests
       ↓
Build Application
       ↓
Deploy Application
       ↓
Updated Website
```

This process reduces manual work.

---

## 7. What is a CI/CD Pipeline?

A CI/CD Pipeline is a sequence of automated steps used to test, build, and deploy an application.

Example:

```text
Source Code
    ↓
Testing
    ↓
Building
    ↓
Deployment
```

Each stage performs a specific task.

For example:

- Testing checks whether the application works.
- Building prepares the application.
- Deployment makes the application available to users.

## 8. Popular CI/CD Tools

| Tool | Purpose |
|---|---|
| GitHub Actions | Automates workflows using GitHub |
| Jenkins | CI/CD automation tool |
| GitLab CI/CD | Automation within GitLab |
| CircleCI | Automates software testing and deployment |
| Azure DevOps | Microsoft's development and deployment platform |

We will mainly use **GitHub Actions** because our projects are already on GitHub.

---

## 9. CI/CD vs Manual Deployment

| Manual Deployment | CI/CD |
|---|---|
| Developer performs steps manually | Steps can run automatically |
| Takes more time | Saves time |
| Repeated manual work | Reusable automation |
| Human errors are possible | Automated checks reduce errors |

---

## 10. Advantages of CI/CD

1. Saves development time.
2. Finds errors early.
3. Reduces manual work.
4. Makes deployment easier.
5. Improves application quality.
6. Helps developers release updates faster.

# 11. Interview Questions & Answers

### Q1. What is CI/CD?

CI/CD is a software development practice that automates code integration, testing, building, and application delivery or deployment.

### Q2. What is Continuous Integration?

Continuous Integration means regularly combining code changes into a shared repository and running automated tests.

### Q3. What is Continuous Delivery?

Continuous Delivery ensures that an application is automatically built and tested and remains ready for release.

### Q4. What is Continuous Deployment?

Continuous Deployment automatically releases successfully tested code to production.

### Q5. What is the difference between Continuous Delivery and Continuous Deployment?

Continuous Delivery may require manual approval before production deployment, whereas Continuous Deployment automatically releases the changes.

### Q6. What is a CI/CD Pipeline?

A CI/CD Pipeline is a sequence of automated steps used to test, build, and deploy applications.

### Q7. Why do we use CI/CD?

We use CI/CD to reduce manual work, detect errors early, and make software releases faster and more reliable.

### Q8. Name some CI/CD tools.

GitHub Actions, Jenkins, GitLab CI/CD, CircleCI, and Azure DevOps.

### Q9. Can CI/CD work with Docker?

Yes. CI/CD can automatically build Docker images, test them, and deploy containers.

### Q10. Can we use CI/CD for Python applications?

Yes. We can automate Python testing, application building, and deployment using CI/CD tools.
