# 4. Automating Python Testing with GitHub Actions 🐍

## 1. What is Automated Testing?

Automated Testing means using code and tools to test our application automatically.

Instead of manually checking everything, we write test cases that verify whether our application works correctly.

Example:

Suppose you have a Python function that adds two numbers.

```python
def add(a, b):
    return a + b
```

We can automatically test it to check whether the result is correct.

---

## 2. What is Pytest?

Pytest is a Python testing framework.

It helps developers write and execute test cases easily.

Install Pytest:

```bash
pip install pytest
```

Example project structure:

```text
MyProject/
    |
    |--- main.py
    |--- test_main.py
    |--- requirements.txt
```

---

## 3. Writing Your First Python Test

### main.py

```python
def add(a, b):
    return a + b
```

### test_main.py

```python
from main import add

def test_add():
    assert add(2, 3) == 5
```

Here:

- `test_add()` is a test function.
- `assert` checks whether the expected result is correct.
- If the condition is true, the test passes.
- If the condition is false, the test fails.

---

## 4. How to Run Python Tests?

Open your terminal inside the project folder.

Run:

```bash
pytest
```

To see more details:

```bash
pytest -v
```

Example successful output:

```text
========================
test_main.py::test_add PASSED
========================
1 passed
```

If the test fails, Pytest displays an error.

---

## 5. What is requirements.txt?

`requirements.txt` contains the Python packages required by our project.

Example:

```text
fastapi
uvicorn
pytest
```

Install all dependencies using:

```bash
pip install -r requirements.txt
```

This makes it easier to install the same dependencies on another machine.

## 6. Automating Python Tests with GitHub Actions

Now let's connect Python testing with GitHub Actions.

Our goal:

Whenever we push code to GitHub, Python tests should run automatically.

### Workflow

```text
Developer Writes Python Code
          |
          ↓
     Push to GitHub
          |
          ↓
   GitHub Actions Starts
          |
          ↓
    Setup Python
          |
          ↓
 Install Dependencies
          |
          ↓
     Run Pytest
          |
          ↓
    Show Test Result
```

---

## 7. Create a GitHub Actions Workflow

Inside your project, create this folder structure:

```text
MyProject/
    |
    |--- main.py
    |--- test_main.py
    |--- requirements.txt
    |
    |--- .github/
           |
           |--- workflows/
                  |
                  |--- python-tests.yml
```

### Add This Workflow Code

Create `python-tests.yml` and add:

```yaml
name: Python Automated Tests

on:
  push:
    branches:
      - main

  pull_request:
    branches:
      - main

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install Dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: Run Tests
        run: pytest -v
```

---

## 8. Understanding the Workflow

| Command | Purpose |
|---|---|
| checkout | Downloads repository code |
| setup-python | Installs the required Python version |
| pip install | Installs project dependencies |
| pytest | Runs Python tests |
| ubuntu-latest | Uses an Ubuntu runner |

### What Happens?

1. You push code to GitHub.
2. GitHub Actions starts the workflow.
3. It downloads your project.
4. It installs Python.
5. It installs dependencies.
6. It runs Pytest.
7. GitHub displays whether the tests passed or failed.

---

## 9. What Happens If a Test Fails?

Imagine your application has a bug.

The expected result is:

```python
assert add(2, 3) == 5
```

But your function returns 6.

Pytest reports a failure.

GitHub Actions also marks the workflow as failed.

This helps developers identify problems before releasing code.

**Important:** A successful test run only confirms that the tests you wrote passed. It does not guarantee that the entire application is bug-free.
