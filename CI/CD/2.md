# 2. GitHub Actions — CI/CD Automation ⚙️

## 1. What is GitHub Actions?

GitHub Actions is an automation tool provided by GitHub.

It helps developers automatically:
- Test code.
- Build applications.
- Run scripts.
- Build Docker images.
- Deploy applications.

**In simple words:**

Whenever you push code to GitHub, GitHub Actions can automatically perform tasks without you doing everything manually.

### Example

You update your Python project and push it to GitHub.

GitHub Actions can automatically run your Python tests.

---

## 2. Why Do We Use GitHub Actions?

- Automate repetitive tasks.
- Run tests automatically.
- Build applications.
- Automate deployment.
- Connect GitHub with Docker and AWS.
- Save development time.

---

## 3. How Does GitHub Actions Work?

Imagine you have a Python project on GitHub.

```text
Developer Writes Code
         |
         ↓
    Push to GitHub
         |
         ↓
  GitHub Actions Starts
         |
         ↓
   Run Automated Tests
         |
         ↓
    Build Application
         |
         ↓
       Deploy
```

GitHub Actions performs the tasks defined in your workflow file.

---

## 4. What is a Workflow?

A Workflow is a set of automated instructions that GitHub Actions follows.

For example, we can create a workflow that runs Python tests whenever we push code.

A workflow is written in a YAML file.

GitHub stores workflow files inside:

```text
.github/workflows/
```

Example project structure:

```text
MyProject/
    |
    |--- main.py
    |--- requirements.txt
    |
    |--- .github/
           |
           |--- workflows/
                  |
                  |--- python.yml
```

---

## 5. What are GitHub Actions Runners?

A Runner is a machine that executes the tasks defined in a workflow.

In simple words:

GitHub provides a machine to run your automation tasks.

Examples:

- Ubuntu
- Windows
- macOS

For most beginner Python projects, we can use Ubuntu.

---

## 6. What are Jobs and Steps?

A **Job** is a group of tasks that run on a runner.

A **Step** is an individual task inside a job.

Example:

```text
Workflow
   |
   ↓
Job
   |
   |--- Step 1: Checkout Code
   |
   |--- Step 2: Install Python
   |
   |--- Step 3: Install Dependencies
   |
   |--- Step 4: Run Tests
```

A workflow can contain multiple jobs.

Jobs can run in parallel or depend on other jobs.

---

## 7. What Triggers a Workflow?

A trigger decides when a workflow should start.

Common triggers:

| Trigger | Meaning |
|---|---|
| push | Runs when code is pushed |
| pull_request | Runs when a pull request event occurs |
| workflow_dispatch | Allows manual execution |
| schedule | Runs at a scheduled time |

Example:

```yaml
on:
  push:
    branches:
      - main
```

This workflow runs when code is pushed to the main branch.

## 9. Interview Questions & Answers

### Q1. What is GitHub Actions?

GitHub Actions is a GitHub automation tool used to automate testing, building, and deployment.

### Q2. What is a Workflow?

A Workflow is a collection of automated instructions that run when a specified event occurs.

### Q3. What is a Runner?

A Runner is a machine that executes GitHub Actions workflow jobs.

### Q4. What is a Job?

A Job is a group of steps that execute on a runner.

### Q5. What is a Step?

A Step is an individual task inside a job.

### Q6. What is a Workflow Trigger?

A trigger decides when a workflow should execute, such as when code is pushed.

### Q7. Where are GitHub Actions workflow files stored?

Inside the `.github/workflows/` directory of a repository.

### Q8. Which file format is used for GitHub Actions?

GitHub Actions uses YAML files.

### Q9. Can GitHub Actions run Python tests?

Yes. It can install Python dependencies and execute automated tests.

### Q10. Can GitHub Actions work with Docker?

Yes. It can build Docker images and push them to container registries.
