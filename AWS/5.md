# 5. IAM — Identity and Access Management 🔐

## 1. What is IAM?

IAM stands for **Identity and Access Management**.

IAM is an AWS service used to manage users and control who can access AWS resources.

In simple words:

IAM decides:
- Who can access AWS?
- What can they access?
- What actions can they perform?

Example:

A developer can access an EC2 server but may not have permission to delete an S3 bucket.

---

## 2. Why Do We Use IAM?

We use IAM to:

- Manage AWS users.
- Control permissions.
- Protect AWS resources.
- Give different access to different people.
- Improve account security.

---

## 3. Important IAM Components

### 1. IAM User

An IAM User represents a person or application that needs access to AWS.

Example:

A company creates an IAM user for its developer.

### 2. IAM Group

An IAM Group is a collection of IAM users.

Example:

```text
Developers Group
    |
    |--- Developer 1
    |--- Developer 2
    |--- Developer 3
```

We can assign permissions to the group instead of managing every user separately.

### 3. IAM Policy

An IAM Policy defines what actions are allowed or denied.

Example:

```text
Developer Permission
    |
    |--- View EC2 instances
    |--- Access S3 files
    |--- Cannot delete resources
```

### 4. IAM Role

An IAM Role provides temporary permissions to a trusted user or AWS service.

Example:

An EC2 server needs permission to access an S3 bucket.

Instead of storing AWS access keys inside the application, we can attach an IAM Role to the EC2 instance.

---

## 4. What are IAM Permissions?

Permissions decide what a user or role can do.

Examples:

- Read files.
- Upload files.
- Create EC2 instances.
- Delete resources.
- View AWS services.

AWS uses two main permission decisions:

- Allow: Permission is granted.
- Deny: Permission is blocked.

An explicit Deny takes priority over an Allow.

---

## 5. Real-Time Example

Imagine a company has three employees:

```text
Company
   |
   |--- Admin
   |      ↓
   |   Full Access
   |
   |--- Developer
   |      ↓
   |   EC2 and S3 Access
   |
   |--- Tester
          ↓
       Limited Access
```

Each employee gets permissions based on their work.

This helps protect important resources.

---

## 6. IAM and Application Security

Suppose you deploy a Python application on EC2.

Your application needs to upload files to S3.

A better approach is:

```text
Python Application
        |
        ↓
    EC2 Server
        |
        ↓
     IAM Role
        |
        ↓
     AWS S3
```

The IAM Role gives the EC2 server permission to access S3.

This avoids storing permanent AWS access keys directly in your application.

---

## 7. IAM vs IAM Role

| IAM User | IAM Role |
|---|---|
| Represents a user or application identity | Provides temporary permissions |
| Can have long-term credentials | Uses temporary credentials |
| Used for user access | Commonly used by AWS services |
| Example: Developer account | Example: EC2 accessing S3 |

---

## 8. Important Security Tips

- Never share your AWS password.
- Never upload AWS access keys to GitHub.
- Enable Multi-Factor Authentication (MFA).
- Give users only the permissions they need.
- Avoid using the root account for daily work.
- Use IAM Roles for AWS services when possible.

## 9. Interview Questions

**Q1. What is IAM?**

IAM is an AWS service used to manage users and control access to AWS resources.

**Q2. What is an IAM User?**

An IAM User represents a person or application that needs access to AWS.

**Q3. What is an IAM Group?**

An IAM Group is a collection of IAM users managed together.

**Q4. What is an IAM Policy?**

An IAM Policy defines which actions are allowed or denied.

**Q5. What is an IAM Role?**

An IAM Role provides temporary permissions to a trusted user or AWS service.

**Q6. Why should we use IAM Roles with EC2?**

They allow EC2 applications to access other AWS services without storing permanent access keys in the application.

**Q7. What is MFA?**

MFA stands for Multi-Factor Authentication. It adds an extra verification step during login.
