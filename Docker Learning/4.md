# 🐳 4. Docker Containers

## 1. What is a Docker Container?

A Docker Container is an isolated environment where an application runs.

A container is created from a Docker Image.

```text
Docker Image
      ↓
Create Container
      ↓
Running Application
```

### Simple Example

Think about a Docker Image as a **blueprint**.

```text
Blueprint
    ↓
Build House
```

Similarly:

```text
Docker Image
    ↓
Create Container
```

### Remember

> **Image = Blueprint**

> **Container = Running instance of an Image**

---

# 2. Why Do We Need Containers?

Containers make it easier to run applications in a separate and controlled environment.

For example, we may have:

```text
Container 1 → Python Application

Container 2 → MySQL

Container 3 → Nginx
```

Each container can run its own application or service.

This helps keep applications separated from each other.

---

# 3. How is a Container Created?

A container is created from a Docker Image.

For example:

```bash
docker run nginx
```

Here:

```text
nginx
  ↓
Docker Image
  ↓
docker run
  ↓
Docker Container
```

If the image is not already available locally, Docker can pull it from a registry such as Docker Hub before creating the container. :contentReference[oaicite:1]{index=1}

---

# 4. `docker run`

The `docker run` command is used to **create and start a new container from an image**. :contentReference[oaicite:2]{index=2}

Example:

```bash
docker run nginx
```

Simple flow:

```text
docker run nginx
       ↓
Find nginx Image
       ↓
Create Container
       ↓
Start Container
       ↓
Nginx Runs
```

---

# 5. Running a Container in Background

Normally, a container can use your terminal while it is running.

To run it in the background, we use:

```bash
docker run -d nginx
```

Here:

```text
-d
 ↓
Detached Mode
 ↓
Run in Background
```

This allows us to continue using our terminal while the container runs. :contentReference[oaicite:3]{index=3}

---

# 6. Giving a Container a Name

Docker can automatically give a container a random name.

We can give it our own name using:

```bash
docker run --name my-nginx nginx
```

Now the container is called:

```text
my-nginx
```

This makes it easier to use later.

For example:

```bash
docker stop my-nginx
```

Docker supports assigning a custom container name with `--name`. :contentReference[oaicite:4]{index=4}

---

# 7. Listing Running Containers

To see currently running containers:

```bash
docker ps
```

Example:

```text
CONTAINER ID   IMAGE   STATUS       NAMES
abc123         nginx   Up 2 minutes my-nginx
```

This command mainly shows containers that are currently running. :contentReference[oaicite:5]{index=5}

---

# 8. Listing All Containers

Sometimes a container has stopped.

To see both running and stopped containers:

```bash
docker ps -a
```

Example:

```text
CONTAINER ID   IMAGE   STATUS
abc123         nginx   Up 5 minutes
xyz456         nginx   Exited
```

### Remember

```text
docker ps
    ↓
Running Containers

docker ps -a
    ↓
All Containers
```

Docker documents `docker ps -a` as the way to view containers including stopped ones. :contentReference[oaicite:6]{index=6}

---

# 9. Starting a Stopped Container

If a container already exists but is stopped, we don't need to create a new one.

We can start it again:

```bash
docker start my-nginx
```

Flow:

```text
Stopped Container
       ↓
docker start
       ↓
Running Container
```

`docker start` starts one or more existing stopped containers. :contentReference[oaicite:7]{index=7}

---

# 10. Stopping a Container

To stop a running container:

```bash
docker stop my-nginx
```

Flow:

```text
Running Container
       ↓
docker stop
       ↓
Stopped Container
```

The container still exists after being stopped. We can start it again later. :contentReference[oaicite:8]{index=8}

---

# 11. Restarting a Container

If we want to stop and start a container again, we can use:

```bash
docker restart my-nginx
```

Flow:

```text
Running Container
       ↓
docker restart
       ↓
Running Again
```

---

# 12. Removing a Container

If we don't need a container anymore, we can remove it.

```bash
docker rm my-nginx
```

Usually, a container needs to be stopped before it can be removed normally.

Flow:

```text
Stopped Container
       ↓
docker rm
       ↓
Container Removed
```

Docker provides `docker container rm` for removing containers. :contentReference[oaicite:9]{index=9}

---

# 13. Container Lifecycle

A simple container lifecycle looks like this:

```text
Docker Image
     ↓
docker run
     ↓
Created + Started
     ↓
Running
     ↓
docker stop
     ↓
Stopped
     ↓
docker start
     ↓
Running Again
     ↓
docker rm
     ↓
Removed
```

### Easy Way to Remember

```text
run    → Create + Start
stop   → Stop
start  → Start Again
restart → Restart
rm     → Remove
```

# 14. Container Logs

Sometimes our application doesn't work as expected.

We can check what the container has printed using:

```bash
docker logs my-nginx
```

Logs are useful for finding errors and understanding what is happening inside the application. Docker's `docker logs` command displays output from a container's process. :contentReference[oaicite:10]{index=10}

### Simple Example

```text
Application
    ↓
Something goes wrong
    ↓
docker logs
    ↓
Check Error / Output
```

---

# 15. Running a Command Inside a Container

Sometimes we need to enter a running container and execute a command inside it.

We can use:

```bash
docker exec -it my-nginx sh
```

This opens a shell inside the running container when the image provides `sh`.

```text
Your Computer
      ↓
docker exec
      ↓
Running Container
      ↓
Container Shell
```

Docker provides `docker exec` specifically for executing commands in a running container. :contentReference[oaicite:11]{index=11}

---

# 16. Container ID and Container Name

Every container has a unique **Container ID**.

For example:

```text
CONTAINER ID
abc123456789
```

A container can also have a name.

Example:

```text
Container ID → abc123456789
Container Name → my-nginx
```

Using a name is often easier:

```bash
docker stop my-nginx
```

instead of:

```bash
docker stop abc123456789
```

---

# 17. Container Ports

A container can run an application on a port.

For example, an Nginx container commonly listens on port `80`.

But the container's port is not automatically available from your computer's browser.

We can map a host port to the container port.

Example:

```bash
docker run -d -p 8080:80 nginx
```

Here:

```text
8080 → Your Computer
80   → Container
```

Flow:

```text
Browser
   ↓
localhost:8080
   ↓
Docker
   ↓
Container Port 80
   ↓
Nginx
```

### Remember

```text
-p HOST_PORT:CONTAINER_PORT
```

So:

```text
-p 8080:80
```

means:

> Send traffic from port `8080` on my computer to port `80` inside the container.

Docker's `-p` / `--publish` option publishes a container port to the host. :contentReference[oaicite:12]{index=12}

# 18. Simple Practical Example

Let's run an Nginx container.

### Step 1 — Run Nginx

```bash
docker run -d --name my-nginx -p 8080:80 nginx
```

### Step 2 — Check Running Containers

```bash
docker ps
```

We should see:

```text
my-nginx
```

### Step 3 — Open Browser

Go to:

```text
http://localhost:8080
```

The Nginx page should appear.

### Step 4 — Stop Container

```bash
docker stop my-nginx
```

### Step 5 — Start Again

```bash
docker start my-nginx
```

### Step 6 — Check Logs

```bash
docker logs my-nginx
```

### Step 7 — Remove Container

First stop it:

```bash
docker stop my-nginx
```

Then remove it:

```bash
docker rm my-nginx
```

# 19. `docker run` vs `docker start`

This is an important difference.

### `docker run`

Creates a **new container** from an image and starts it. :contentReference[oaicite:13]{index=13}

```bash
docker run nginx
```

### `docker start`

Starts an **existing stopped container**. :contentReference[oaicite:14]{index=14}

```bash
docker start my-nginx
```

### Easy Way to Remember

```text
docker run
     ↓
New Container

docker start
     ↓
Existing Container
```

---

# 20. `docker stop` vs `docker rm`

### `docker stop`

Stops the container but keeps it.

```bash
docker stop my-nginx
```

### `docker rm`

Removes the container.

```bash
docker rm my-nginx
```

### Easy Way to Remember

```text
stop
 ↓
Container stays


rm
 ↓
Container is removed
```

# 21. Useful Container Commands

| Command | What it does |
|---|---|
| `docker run` | Create and start a new container |
| `docker ps` | Show running containers |
| `docker ps -a` | Show all containers |
| `docker start` | Start a stopped container |
| `docker stop` | Stop a running container |
| `docker restart` | Restart a container |
| `docker rm` | Remove a container |
| `docker logs` | Show container logs |
| `docker exec` | Run a command inside a running container |
| `docker inspect` | Show detailed container information |

These commands are part of Docker's container management commands. :contentReference[oaicite:15]{index=15}

# ❓ Interview Q&A

## Q1. What is a Docker Container?

**Answer:**

A Docker Container is an isolated environment where an application runs with its required dependencies.

---

## Q2. How is a container created?

**Answer:**

A container is created from a Docker Image, usually using the `docker run` command.

---

## Q3. What does `docker run` do?

**Answer:**

`docker run` creates and starts a new container from a Docker Image.

---

## Q4. What is the difference between `docker run` and `docker start`?

**Answer:**

`docker run` creates and starts a new container, while `docker start` starts an existing stopped container.

---

## Q5. How do you see running containers?

**Answer:**

We use:

```bash
docker ps
```

---

## Q6. How do you see all containers?

**Answer:**

We use:

```bash
docker ps -a
```

This includes stopped containers.

---

## Q7. How do you stop a container?

**Answer:**

We use:

```bash
docker stop container-name
```

---

## Q8. How do you start a stopped container?

**Answer:**

We use:

```bash
docker start container-name
```

---

## Q9. How do you remove a container?

**Answer:**

We use:

```bash
docker rm container-name
```

---

## Q10. How do you check container logs?

**Answer:**

We use:

```bash
docker logs container-name
```

It helps us see the output and errors produced by the container.

---

## Q11. How do you execute a command inside a running container?

**Answer:**

We can use:

```bash
docker exec -it container-name sh
```

---

## Q12. What is port mapping?

**Answer:**

Port mapping connects a port on our computer to a port inside the Docker container.

For example:

```bash
docker run -p 8080:80 nginx
```

Here, port `8080` on our computer is connected to port `80` inside the container.

---

## Q13. Can a stopped container be started again?

**Answer:**

Yes. We can use `docker start` to start an existing stopped container.

---

## Q14. Can multiple containers run on the same machine?

**Answer:**

Yes. Multiple containers can run on the same machine, and each can run a different application or service.

---

# 🎯 Key Takeaways

- A Container is where an application runs.
- Containers are created from Images.
- `docker run` creates and starts a new container.
- `docker ps` shows running containers.
- `docker ps -a` shows all containers.
- `docker stop` stops a container.
- `docker start` starts a stopped container.
- `docker restart` restarts a container.
- `docker rm` removes a container.
- `docker logs` helps us check application output and errors.
- `docker exec` allows us to run commands inside a running container.
- `-p` is used for port mapping.
