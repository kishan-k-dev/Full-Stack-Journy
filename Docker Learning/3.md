# 🐳 3. Docker Images

## 1. What is a Docker Image?

A **Docker Image** is a ready-to-use package or blueprint that contains everything needed to create and run a container.

It can contain:

- Application code
- Required libraries
- Dependencies
- Runtime
- Basic configuration

### Simple Example

Imagine a house blueprint.

```text
House Blueprint
      ↓
   Build House
```

Docker works similarly:

```text
Docker Image
      ↓
Create Container
      ↓
Running Application
```

### Remember

> **Image = Blueprint**

---

# 2. Why Do We Need Docker Images?

A Docker Container needs something from which it can be created.

That something is a **Docker Image**.

For example, if we want to run a Python application:

```text
Python Image
     ↓
Create Container
     ↓
Python Application Runs
```

Without an image, Docker doesn't have the packaged environment needed to create that container.

---

# 3. What Does a Docker Image Contain?

A Docker Image can contain the things required by an application.

For example, a Python application may need:

```text
Python
Flask
Requests
Application Code
Configuration
```

These can be packaged into an image.

```text
Docker Image
     │
     ├── Python
     ├── Flask
     ├── Libraries
     ├── Application Code
     └── Configuration
```

When a container is created from the image, the application can run using those packaged components.

---

# 4. Image vs Container

This is one of the most important things to understand.

```text
Docker Image
     ↓
Create / Run
     ↓
Docker Container
```

### Simple Example

Think about a mobile application.

```text
APK File
   ↓
Install
   ↓
Running Application
```

Similarly:

```text
Docker Image
   ↓
Run
   ↓
Docker Container
```

### Easy Way to Remember

> **Image = Blueprint**

> **Container = Running instance of the Image**

---

# 5. Where Do Docker Images Come From?

Docker Images can come from different places.

The most common source is **Docker Hub**.

```text
Docker Hub
     ↓
Docker Image
     ↓
Your Computer
     ↓
Docker Container
```

We can also:

- Build our own image
- Use images from Docker Hub
- Use images from private registries

---

# 6. Pulling an Image

If an image is available on Docker Hub, we can download it using:

```bash
docker pull nginx
```

Here:

```text
docker pull
     ↓
Download an Image
```

Example:

```bash
docker pull python
```

This downloads the Python image to our computer.

### Flow

```text
Docker Hub
     ↓
docker pull python
     ↓
Local Computer
     ↓
Python Image
```

---

# 7. Listing Docker Images

To see the images available on our computer, use:

```bash
docker images
```

or:

```bash
docker image ls
```

Example output may look like:

```text
REPOSITORY    TAG       IMAGE ID       CREATED       SIZE
python        latest    abc123         ...           ...
nginx         latest    xyz456         ...           ...
```

We will understand these columns later.

For now, remember:

> `docker images` → Shows the Docker Images available locally.

---

# 8. Image Name and Tag

Docker Images usually have a name and a **tag**.

Example:

```text
python:3.12
```

Here:

```text
python → Image name
3.12   → Tag
```

Another example:

```text
nginx:latest
```

Here:

```text
nginx  → Image name
latest → Tag
```

### Why Are Tags Useful?

Different versions of the same application can have different tags.

Example:

```text
python:3.10
python:3.11
python:3.12
```

This allows us to choose the version we need.

---

# 9. What is `latest`?

You may often see:

```text
nginx:latest
```

`latest` is a tag commonly used to refer to a particular default/latest-published version of an image.

It does **not always mean the newest version available**.

For important projects, it is better to understand and choose the version you actually want.

Example:

```text
python:3.12
```

is more specific than:

```text
python:latest
```

---

# 10. Image IDs

Every Docker Image has an **Image ID**.

Example:

```text
REPOSITORY    TAG       IMAGE ID
python        3.12      abc123
```

The Image ID helps Docker identify a particular image.

You normally don't need to memorize Image IDs.

---

# 11. Image Layers

Docker Images are made up of **layers**.

Each instruction used while building an image can create a layer.

For example:

```text
Layer 4 → Application Code
Layer 3 → Dependencies
Layer 2 → Working Directory
Layer 1 → Python Base Image
```

So we can think of an image like:

```text
        Docker Image
             ↓
    ┌─────────────────┐
    │ Application Code │
    ├─────────────────┤
    │ Dependencies     │
    ├─────────────────┤
    │ Python           │
    ├─────────────────┤
    │ Base Image       │
    └─────────────────┘
```

### Why Are Layers Useful?

Docker can reuse layers when possible.

This can make image building faster and avoid unnecessary work.

We will learn image layers in more detail when we learn **Dockerfile and image building**.

---

# 12. Base Image

A **base image** is an existing image that we use as the starting point for our own image.

For example:

```dockerfile
FROM python:3.12
```

Here:

```text
python:3.12
      ↓
Base Image
```

Then we can add our application on top of it.

```text
Python Base Image
       ↓
Install Dependencies
       ↓
Add Application
       ↓
Our Docker Image
```

---

# 13. Building Our Own Image

We can create our own Docker Image instead of only downloading images.

For example, suppose we have:

```text
app.py
requirements.txt
Dockerfile
```

We can create an image using:

```bash
docker build -t my-python-app .
```

Here:

```text
docker build → Build an Image
-t            → Give the Image a name/tag
my-python-app → Image name
.             → Use the current directory
```

### Flow

```text
Application Files
       ↓
Dockerfile
       ↓
docker build
       ↓
Docker Image
```

We will learn Dockerfile and `docker build` properly in the next topics.

---

# 14. Running a Container From an Image

After we have an image, we can create a container from it.

Example:

```bash
docker run nginx
```

The basic idea is:

```text
nginx Image
     ↓
docker run
     ↓
nginx Container
     ↓
Running nginx
```

So:

> `docker pull` → Get an image

> `docker run` → Create and run a container from an image

---

# 15. Removing an Image

If we no longer need an image, we can remove it.

Example:

```bash
docker rmi nginx
```

or:

```bash
docker image rm nginx
```

Remember:

> `docker rmi` → Remove an image

Docker may not allow removal if the image is still being used by containers.

---

# 16. Docker Image Workflow

The basic image workflow is:


# 🌎 Simple Real-World Example

Suppose I want to create a Python application.

First, I need a Python environment.

I can get the Python image:

```bash
docker pull python:3.12
```

Now:

```text
Docker Hub
     ↓
python:3.12
     ↓
Local Docker Image
```

Then I can create a container:

```bash

```

Flow:

```text
Python Image
     ↓
Docker Run
     ↓
Python Container
     ↓
Python Environment
```

Later, we can create our own image containing our actual Python application.

# ❓ Interview Q&A

## Q1. What is a Docker Image?

**Answer:**

A Docker Image is a packaged template used to create and run Docker containers.

---

## Q2. What does a Docker Image contain?

**Answer:**

A Docker Image can contain the application code, dependencies, libraries, runtime, and required configuration.

---

## Q3. What is the difference between an Image and a Container?

**Answer:**

An Image is a blueprint used to create a container, while a Container is the running instance created from that image.

---

## Q4. How do you download a Docker Image?

**Answer:**

We can use the `docker pull` command.

Example:

```bash
docker pull python
```

---

## Q5. How do you see Docker Images on your computer?

**Answer:**

We can use:

```bash
docker images
```

or:

```bash
docker image ls
```

---

## Q6. What is a Docker Image tag?

**Answer:**

A tag is used to identify a particular version or variant of an image.

Example:

```text
python:3.12
```

Here `3.12` is the tag.

---

## Q7. What is a base image?

**Answer:**

A base image is an existing image that we use as the starting point for creating our own Docker Image.

---

## Q8. What are Docker Image layers?

**Answer:**

Docker Images are built using multiple layers. Each layer represents part of the image, and Docker can reuse unchanged layers to make builds more efficient.

---

## Q9. How do you build a Docker Image?

**Answer:**

We use the `docker build` command with a Dockerfile.

Example:

```bash
docker build -t my-app .
```

---

## Q10. How do you remove a Docker Image?

**Answer:**

We can use:

```bash
docker rmi image-name
```

---

## Q11. What is the difference between `docker pull` and `docker run`?

**Answer:**

`docker pull` downloads an image, while `docker run` creates and starts a container from an image.

---

## Q12. Where can Docker Images be stored?

**Answer:**

Docker Images can be stored in Docker registries such as Docker Hub or private registries.

---

# 🎯 Key Takeaways

- A Docker Image is a blueprint/package used to create containers.
- Images contain the things required to run an application.
- Images can be downloaded from Docker Hub.
- `docker pull` downloads an image.
- `docker images` shows local images.
- `docker build` creates an image from a Dockerfile.
- `docker run` creates and starts a container from an image.
- Images are made up of layers.
- A base image is the starting point for building another image.
- Tags help identify different image versions.
- `docker rmi` removes an image.
