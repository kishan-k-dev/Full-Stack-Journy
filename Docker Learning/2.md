# 🐳 2. Docker Architecture

## 1. What is Docker Architecture?

Docker Architecture means **how the different parts of Docker work together**.

When we use a Docker command, different Docker components communicate with each other to perform the requested task.

### Simple View

```text
You
 ↓
Docker Client
 ↓
Docker Daemon
 ↓
Docker Engine
 ↓
Images / Containers
```

We will understand each part one by one.

---

# 2. Main Components of Docker

The main Docker components are:

- Docker Client
- Docker Daemon
- Docker Engine
- Docker Image
- Docker Container
- Docker Registry
- Docker Hub

A simple view is:

```text
                Docker
                   ↓
        ┌──────────┴──────────┐
        ↓                     ↓
 Docker Client          Docker Daemon
                              ↓
                        Docker Engine
                              ↓
                  ┌───────────┴───────────┐
                  ↓                       ↓
              Images                 Containers
                  ↑
                  │
           Docker Registry
                  ↑
                  │
             Docker Hub
```

---

# 3. Docker Client

The **Docker Client** is what we use to communicate with Docker.

Usually, we use the Docker command in the terminal.

For example:

```bash
docker ps
```

or:

```bash
docker run nginx
```

The Docker Client takes our command and sends it to the Docker Daemon.

### Simple Example

```text
You type:
docker ps
     ↓
Docker Client
     ↓
Docker Daemon
```

### Easy Definition

> **Docker Client = The way we give commands to Docker.**

---

# 4. Docker Daemon

The **Docker Daemon** is a background service that does the actual Docker work.

It listens for Docker commands and manages things like:

- Containers
- Images
- Networks
- Volumes

For example, when we type:

```bash
docker run nginx
```

the Docker Client sends the request to the Docker Daemon.

The Docker Daemon then handles the request.

```text
You
 ↓
Docker Client
 ↓
Docker Daemon
 ↓
Run Container
```

### Easy Definition

> **Docker Daemon = The background service that performs Docker tasks.**

---

# 5. Docker Engine

Docker Engine is the main technology that allows us to **build and run containers**.

It includes the components needed to manage Docker containers and images.

A simple way to understand it:

```text
Docker Engine
      ↓
Manages
      ↓
Images
Containers
Networks
Volumes
```

### Easy Definition

> **Docker Engine = The core system that makes Docker work.**

---

# 6. Docker Image

A Docker Image is a **blueprint/template** used to create containers.

For example:

```text
Python Image
     ↓
Python Container
```

An image can contain:

- Application code
- Libraries
- Dependencies
- Runtime
- Required configuration

### Easy Example

Think about a house.

```text
House Blueprint
      ↓
Build House
```

Docker works similarly:

```text
Docker Image
      ↓
Create Container
```

### Remember

> **Image = Blueprint**

---

# 7. Docker Container

A Docker Container is where the application actually runs.

A container is created from a Docker Image.

```text
Docker Image
     ↓
Create Container
     ↓
Running Application
```

### Example

If we have a Python image:

```text
Python Image
     ↓
Python Container
     ↓
Python Application
```

### Remember

> **Container = Running instance created from an Image**

---

# 8. Docker Registry

A **Docker Registry** is a place where Docker Images are stored.

Think of it like a storage system for Docker Images.

```text
Docker Image
     ↓
Registry
     ↓
Store Image
```

A registry can be:

- Public
- Private

Developers can push images to a registry and pull them when needed.

---

# 9. Docker Hub

**Docker Hub** is a popular public Docker Registry.

It allows developers to:

- Store Docker Images
- Share Docker Images
- Download Docker Images

For example:

```text
Developer
    ↓
Build Image
    ↓
Push Image
    ↓
Docker Hub
```

Another developer can then:

```text
Docker Hub
    ↓
Pull Image
    ↓
Run Container
```

### Easy Definition

> **Docker Hub = A popular place to store and share Docker Images.**

---

# 10. How Docker Components Work Together

Now let's understand the complete flow.

Suppose we type:

```bash
docker run nginx
```

What happens?

### Step 1

We type the command.

```text
docker run nginx
```

### Step 2

The Docker Client receives the command.

```text
You
 ↓
Docker Client
```

### Step 3

The Docker Client sends the request to the Docker Daemon.

```text
Docker Client
      ↓
Docker Daemon
```

### Step 4

The Docker Daemon checks whether the `nginx` image is available locally.

```text
Is nginx image available?
       ↓
   Yes / No
```

### Step 5

If the image is not available locally, Docker can pull it from a registry such as Docker Hub.

```text
Docker Daemon
      ↓
Docker Hub
      ↓
nginx Image
```

### Step 6

Docker uses the image to create a container.

```text
nginx Image
     ↓
Container
```

### Step 7

The container starts and the application runs.

```text
nginx Image
     ↓
nginx Container
     ↓
Running nginx
```

### Complete Flow

```text
You
 ↓
docker run nginx
 ↓
Docker Client
 ↓
Docker Daemon
 ↓
Check Image
 ↓
If needed → Docker Hub
 ↓
Get Image
 ↓
Create Container
 ↓
Start Container
 ↓
Running Application
```

# 13. Client-Server Idea

Docker follows a client-server style architecture.

The **Docker Client** sends requests.

The **Docker Daemon** receives those requests and performs the work.

```text
Docker Client
     │
     │ Docker Commands
     ↓
Docker Daemon
     │
     ↓
Docker Resources
```

Docker Client and Docker Daemon can be on the same machine or communicate remotely.

For our learning, we will mainly use them on our own computer.

# 15. Local Image vs Docker Hub

It is important to understand that Docker does not always need to download an image from Docker Hub.

If the image already exists on your computer:

```text
docker run python
       ↓
Check Local Images
       ↓
Image Found
       ↓
Create Container
```

If it doesn't exist:

```text
docker run python
       ↓
Check Local Images
       ↓
Image Not Found
       ↓
Docker Registry
       ↓
Download Image
       ↓
Create Container
```

# ❓ Interview Q&A

## Q1. What is Docker Architecture?

**Answer:**

Docker Architecture describes how Docker components such as the Client, Daemon, Engine, Images, Containers, and Registry work together.

---

## Q2. What is Docker Client?

**Answer:**

Docker Client is the command-line interface we use to give commands to Docker.

---

## Q3. What is Docker Daemon?

**Answer:**

Docker Daemon is a background service that receives Docker requests and manages containers, images, networks, and volumes.

---

## Q4. What is Docker Engine?

**Answer:**

Docker Engine is the core technology that allows us to build and run Docker containers.

---

## Q5. What is Docker Registry?

**Answer:**

A Docker Registry is a place where Docker Images are stored and shared.

---

## Q6. What is Docker Hub?

**Answer:**

Docker Hub is a popular public registry used to store and share Docker Images.

---

## Q7. What happens when we run `docker run nginx`?

**Answer:**

Docker checks whether the nginx image is available locally. If it is not available, Docker can pull the image from a registry such as Docker Hub. Then Docker creates and starts a container using that image.

---

## Q8. What is the difference between Docker Image and Docker Container?

**Answer:**

A Docker Image is a blueprint used to create a container, while a Docker Container is the environment where the application runs.

---

## Q9. How does the Docker Client communicate with the Docker Daemon?

**Answer:**

The Docker Client sends Docker commands or requests to the Docker Daemon, and the Daemon performs the requested operations.

---

## Q10. Can Docker Client and Docker Daemon run on the same machine?

**Answer:**

Yes. In normal local Docker usage, the Docker Client and Docker Daemon commonly run on the same machine.

---

# 🎯 Key Takeaways

- **Docker Engine** is the core technology that runs Docker.
- **Docker Image** is a blueprint.
- **Docker Container** runs the application.
- **Docker Registry** stores Docker Images.
- **Docker Hub** is a popular public registry.
