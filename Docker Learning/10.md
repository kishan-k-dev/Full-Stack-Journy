# 🧠 10. Recursion

Recursion is a programming technique where a function **calls itself** to solve a problem.

Instead of solving the entire problem at once, recursion breaks the problem into smaller versions of the same problem.

---

# 1. What is Recursion?

A recursive function is a function that calls itself.

Simple example:

```python
def hello():
    print("Hello")
    hello()
```

This function keeps calling itself forever.

That is a problem because there is no stopping condition.

A proper recursive function needs a **base case**.

---

# 2. Two Important Parts of Recursion

Every recursive solution usually has two main parts:

```text
Recursive Function
       |
       +---- Base Case
       |
       +---- Recursive Case
```

## Base Case

The condition that stops recursion.

## Recursive Case

The part where the function calls itself with a smaller or simpler problem.

---

# 3. Basic Recursive Example

Let's print numbers from `1` to `5`.

```python
def print_numbers(n):

    if n == 0:
        return

    print_numbers(n - 1)

    print(n)


print_numbers(5)
```

Output:

```text
1
2
3
4
5
```

Notice:

```python
print_numbers(n - 1)
```

The function keeps calling itself with a smaller value.

---

# 4. How Recursion Works

For:

```python
print_numbers(5)
```

The calls happen like this:

```text
print_numbers(5)
    ↓
print_numbers(4)
    ↓
print_numbers(3)
    ↓
print_numbers(2)
    ↓
print_numbers(1)
    ↓
print_numbers(0)
```

At:

```python
n == 0
```

the recursion stops.

Then the functions return in reverse order.

```text
print_numbers(0)
    ↑
print_numbers(1)
    ↑
print_numbers(2)
    ↑
print_numbers(3)
    ↑
print_numbers(4)
    ↑
print_numbers(5)
```

That's why the output becomes:

```text
1
2
3
4
5
```

---

# 5. Base Case

The base case is extremely important.

Example:

```python
def count_down(n):

    if n == 0:
        return

    print(n)

    count_down(n - 1)
```

Here:

```python
if n == 0:
    return
```

is the base case.

Without it:

```python
def count_down(n):
    print(n)
    count_down(n - 1)
```

the function would continue indefinitely until Python raises a recursion-related error.

---

# 6. Recursive Case

The recursive case is where the function calls itself.

```python
count_down(n - 1)
```

Here the problem becomes smaller:

```text
n
↓
n - 1
↓
n - 2
↓
n - 3
```

This is the basic idea behind recursion.

---

# 7. General Structure of Recursion

A common recursive function looks like:

```python
def recursive_function(problem):

    if base_condition:
        return result

    # solve part of the problem

    return recursive_function(smaller_problem)
```

Remember:

```text
Base Case
   ↓
Stop

Recursive Case
   ↓
Make problem smaller
   ↓
Call function again
```

---

# 8. Recursion and Call Stack

Recursion uses the **call stack**.

Suppose:

```python
def fun(n):

    if n == 0:
        return

    print(n)
    fun(n - 1)
```

Calling:

```python
fun(3)
```

creates:

```text
fun(3)
 ↓
fun(2)
 ↓
fun(1)
 ↓
fun(0)
```

The stack grows as functions are called.

Then functions return:

```text
fun(0) returns
 ↓
fun(1) returns
 ↓
fun(2) returns
 ↓
fun(3) returns
```

---

# 9. Stack Visualization

For:

```python
fun(3)
```

The call stack can be visualized as:

```text
| fun(1) |
| fun(2) |
| fun(3) |
---------
```

After the base case:

```text
fun(1) returns
fun(2) returns
fun(3) returns
```

The stack gets smaller.

# 12. Factorial Using Recursion

Factorial of `n` is:

```text
n! = n × (n-1) × (n-2) × ... × 1
```

Example:

```text
5! = 5 × 4 × 3 × 2 × 1
   = 120
```

Mathematically:

```text
n! = n × (n-1)!
```

Base case:

```text
0! = 1
```

---

# 13. Recursive Factorial Code

```python
def factorial(n):

    if n == 0:
        return 1

    return n * factorial(n - 1)


print(factorial(5))
```

Output:

```text
120
```

---

# 14. Factorial Dry Run

For:

```python
factorial(5)
```

The calls are:

```text
factorial(5)
    ↓
5 × factorial(4)
    ↓
5 × 4 × factorial(3)
    ↓
5 × 4 × 3 × factorial(2)
    ↓
5 × 4 × 3 × 2 × factorial(1)
    ↓
5 × 4 × 3 × 2 × 1 × factorial(0)
```

Base case:

```text
factorial(0) = 1
```

Returning:

```text
1
↓
1 × 1 = 1
↓
2 × 1 = 2
↓
3 × 2 = 6
↓
4 × 6 = 24
↓
5 × 24 = 120
```

Final answer:

```text
120
```

---

# 15. Factorial Complexity

For:

```python
factorial(n)
```

There are approximately `n` function calls.

Time:

```text
O(n)
```

Recursive call stack:

```text
O(n)
```

So:

```text
Time  = O(n)
Space = O(n)
```

```python
def reverse_string(s):

    return reverse_string(s[1:]) + s[0]

```

Output:

```text

```

The idea:

```text

 ↓

llo + e + h
 ↓

 ↓
o + l + l + e + h
```

# 19. Check Palindrome Using Recursion

A palindrome reads the same forward and backward.

Examples:

```text
madam
racecar
level
```

We can compare the first and last characters.

```python
def is_palindrome(s, left, right):

    if left >= right:
        return True

    if s[left] != s[right]:
        return False

    return is_palindrome(s, left + 1, right - 1)


s = "madam"

print(is_palindrome(s, 0, len(s) - 1))
```

Output:

```text
True
```

The search area becomes smaller:

```text
m a d a m
↑       ↑

  a d a
  ↑   ↑

    d
```

# 21. Find Maximum Using Recursion

```python
def find_max(arr, index):

    if index == len(arr) - 1:
        return arr[index]

    remaining_max = find_max(arr, index + 1)

    return max(arr[index], remaining_max)


arr = [10, 50, 20, 80, 30]

print(find_max(arr, 0))
```

Output:

```text
80
```

# 22. Recursion Tree

Some recursive problems create multiple recursive calls.

Example:

```python
def fun(n):

    if n <= 1:
        return

    fun(n - 1)
    fun(n - 2)
```

For:

```text
fun(4)
```

the calls look like:

```text
             fun(4)
            /      \
       fun(3)      fun(2)
       /   \       /   \
   fun(2) fun(1) fun(1) fun(0)
   /   \
fun(1) fun(0)
```

This is called a **recursion tree**.

Recursion trees are especially important when learning Dynamic Programming.

# 23. Fibonacci Using Recursion

Fibonacci sequence:

```text
0 1 1 2 3 5 8 13 21 ...
```

The mathematical definition is:

```text
F(n) = F(n-1) + F(n-2)
```

Base cases:

```text
F(0) = 0
F(1) = 1
```

---

# 24. Recursive Fibonacci Code

```python
def fibonacci(n):

    if n == 0:
        return 0

    if n == 1:
        return 1

    return fibonacci(n - 1) + fibonacci(n - 2)


print(fibonacci(6))
```

Output:

```text
8
```

---

# 25. Why Simple Fibonacci Recursion Is Slow

Consider:

```text
fibonacci(5)
```

It calls:

```text
fibonacci(4)
fibonacci(3)
```

Then those functions call the same calculations again.

For example:

```text
fibonacci(4)
    |
    +---- fibonacci(3)
    |
    +---- fibonacci(2)
```

The same values are calculated multiple times.

This creates a large recursion tree.

The time complexity of the simple recursive Fibonacci implementation is exponential.

Approximately:

```text
O(2^n)
```

This is why we later use **Dynamic Programming** to optimize such problems.

# 26. Recursion vs Iteration

The same problem can often be solved using a loop.

Example: factorial.

### Recursion

```python
def factorial(n):

    if n == 0:
        return 1

    return n * factorial(n - 1)
```

### Iteration

```python
def factorial(n):

    result = 1

    for i in range(1, n + 1):
        result *= i

    return result
```

Both produce:

```text
5! = 120
```

---

# 27. Recursion vs Iteration

| Feature | Recursion | Iteration |
|---|---|---|
| Uses function calls | Yes | No |
| Uses loops | Usually no | Yes |
| Uses call stack | Yes | Usually no |
| Code can be shorter | Sometimes | Sometimes |
| Extra stack memory | Possible | Usually O(1) |
| Useful for trees/graphs | Very useful | Also possible |
| Risk of stack overflow | Yes | Much lower |

# 29. Recursion in Trees

Trees are naturally recursive structures.

Example:

```text
        10
       /  \
      5    20
     / \
    2   7
```

The left side is itself a tree.

The right side is also itself a tree.

So we can write:

```python
def traverse(node):

    if node is None:
        return

    traverse(node.left)
    traverse(node.right)
```

This idea becomes very important in the Trees topic.

# 30. Recursion in Divide and Conquer

Divide and Conquer breaks a problem into smaller parts.

Examples:

```text
Merge Sort
Quick Sort
Binary Search
```

General idea:

```text
Large Problem
     ↓
Divide
     ↓
Smaller Problems
     ↓
Solve recursively
     ↓
Combine results
```

For example, Merge Sort:

```text
             Array
               |
          Divide into half
          /             \
      Left              Right
       |                  |
    Divide             Divide
       |                  |
   smaller            smaller
   arrays              arrays
```

# 33. How to Think About a Recursive Problem

When you see a recursion problem, ask:

### Question 1

What is the smallest possible input?

That becomes the:

```text
Base Case
```

### Question 2

How can I make the problem smaller?

That becomes the:

```text
Recursive Case
```

### Question 3

What should the function return?

Decide what information should come back from the recursive call.

---

# 34. Example — Recursive Factorial Thinking

Problem:

```text
Find factorial(n)
```

Ask:

### Smallest case?

```text
factorial(0) = 1
```

Therefore:

```python
if n == 0:
    return 1
```

### Smaller problem?

```text
factorial(n - 1)
```

### Relationship?

```text
factorial(n) = n × factorial(n - 1)
```

Final code:

```python
def factorial(n):

    if n == 0:
        return 1

    return n * factorial(n - 1)
```

This is the correct way to design recursion instead of trying to memorize code.

# 35. Common Recursion Mistakes

## Mistake 1 — No Base Case

Wrong:

```python
def fun(n):
    fun(n - 1)
```

There is no stopping condition.

---

## Mistake 2 — Base Case Never Reached

Wrong:

```python
def fun(n):

    if n == 0:
        return

    fun(n + 1)
```

If starting with positive `n`, the function moves farther away from `0`.

Correct:

```python
fun(n - 1)
```

---

## Mistake 3 — Forgetting Return

Sometimes the recursive result needs to be returned.

Wrong:

```python
def factorial(n):

    if n == 0:
        return 1

    factorial(n - 1)
```

Correct:

```python
def factorial(n):

    if n == 0:
        return 1

    return n * factorial(n - 1)
```

---

## Mistake 4 — Incorrect Base Case

For example:

```python
def factorial(n):

    if n == 1:
        return 1
```

This can work for positive integers, but you must be careful if `0` is allowed.

A common definition is:

```text
0! = 1
```

---

## Mistake 5 — Too Many Recursive Calls

Some recursive algorithms create many repeated calculations.

Example:

```text
Naive Fibonacci
```

This can lead to very high time complexity.

---

# 36. Recursion Depth

Python has a recursion depth limit.

Very deep recursion can cause:

```text
RecursionError
```

For example, avoid using recursion for extremely large linear operations when a simple loop would work better.

---

# 37. Time and Space Complexity of Recursion

Recursion complexity depends on the number of calls.

### One recursive call per level

Example:

```python
solve(n - 1)
```

Usually:

```text
Time = O(n)
Space = O(n)
```

because of the call stack.

### Two recursive calls per level

Example:

```python
solve(n - 1)
solve(n - 2)
```

This can become exponential.

Example:

```text
Naive Fibonacci
```

Approximately:

```text
Time = O(2^n)
```

The exact complexity can depend on the recurrence and implementation.

# 39. Interview Questions & Answers

## Q1. What is recursion?

**Answer:**

Recursion is a technique where a function calls itself to solve smaller versions of the same problem.

---

## Q2. What are the two important parts of recursion?

**Answer:**

The two main parts are the base case, which stops recursion, and the recursive case, which makes the problem smaller and calls the function again.

---

## Q3. What is a base case?

**Answer:**

A base case is the condition that stops further recursive calls.

---

## Q4. What happens if there is no base case?

**Answer:**

The recursive calls continue until the program reaches the language's recursion limit or stack capacity, resulting in an error.

---

## Q5. What is a call stack?

**Answer:**

The call stack is the memory structure that keeps track of active function calls, including recursive calls.

---

## Q6. What is the difference between recursion and iteration?

**Answer:**

Recursion solves a problem through repeated function calls, while iteration usually solves it using loops. Recursion uses the call stack for active calls.

---

## Q7. What is the space complexity of simple recursive factorial?

**Answer:**

`O(n)` because there can be `n` active function calls on the call stack.

---

## Q8. Why is recursive Fibonacci inefficient?

**Answer:**

Because the same Fibonacci values are calculated repeatedly, creating a large recursion tree and exponential time complexity.

---

## Q9. Can every recursive problem be solved iteratively?

**Answer:**

Many recursive problems can be converted to iterative solutions, usually by using loops and sometimes an explicit stack. However, recursion can be much more natural for structures such as trees.

---

## Q10. Where is recursion commonly used?

**Answer:**

Recursion is commonly used in tree traversal, graph traversal, divide-and-conquer algorithms, backtracking, dynamic programming, Merge Sort, Quick Sort, and Binary Search.

---

# 42. Key Takeaways

- Recursion means a function calls itself.
- Every recursive solution needs a stopping condition.
- The stopping condition is called the base case.
- The recursive case should move toward the base case.
- Recursive calls are stored on the call stack.
- Recursion can make complex problems easier to express.
- Recursion is especially useful for trees, graphs, divide-and-conquer, and backtracking.
- Recursive factorial takes `O(n)` time and `O(n)` call-stack space.
- Naive recursive Fibonacci has exponential time complexity.
- Not every problem needs recursion; sometimes iteration is simpler and more memory efficient.
- Understanding the recursive relationship is more important than memorizing recursive code.

---

# 🧠 Final Interview Tip

When you get a recursion problem, don't immediately start coding.

Think in this order:

```text
1. What is the smallest case?
          ↓
2. What is my base case?
          ↓
3. How can I make the problem smaller?
          ↓
4. What should the recursive call return?
          ↓
5. What is the time complexity?
          ↓
6. What is the call-stack space?
```

For example:

```text
Factorial

Base:
factorial(0) = 1

Smaller problem:
factorial(n - 1)

Relationship:
factorial(n) = n × factorial(n - 1)
```

Once you can think this way, recursion becomes much easier.
