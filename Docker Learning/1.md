# 🐳 1. Docker Introduction & Basics

## 1. What is Docker?

Docker is a tool that helps us **run an application with everything it needs in one package**.

For example, imagine I create a Python application on my laptop.

My application needs:

- Python
- Flask
- Some Python libraries
- A particular version of those libraries

If I give my application to another developer, they may not have the same setup.

Docker helps us package the application and its required dependencies together.

### Simple Example

```text
My Application
      +
Python
      +
Required Libraries
      ↓
    Docker
      ↓
  Container
      ↓
Application Runs
```

### In Simple Words

> **Docker helps us run an application in a consistent environment without worrying too much about different system setups.**

---

# 2. Why Docker?

Let's understand with a simple example.

Suppose I create a Python application on my computer.

It works perfectly on my laptop.

I send the project to my friend.

My friend runs it and gets an error.

Why?

Maybe:

```text
My Computer
Python 3.12
Flask 3.0
Library A
      ↓
Application Works


Friend's Computer
Python 3.10
Flask 2.0
Library B
      ↓
Application Doesn't Work
```

This is one of the problems Docker helps solve.

With Docker, we can package the application and its required environment together.

```text
Application
     +
Required Dependencies
     ↓
Docker Image
     ↓
Docker Container
     ↓
Application Runs
```

### Easy Definition

> **We use Docker to make applications easier and more consistent to run on different machines.**

---

# 3. Problems Docker Solves

Docker mainly helps us with these problems.

### 1. Different Dependencies

One computer may have different versions of libraries.

### 2. Different Environments

The developer's computer and the production server may have different setups.

### 3. Difficult Setup

A new developer may need to install many things before running the project.

### 4. "Works on My Machine"

The application works on one computer but doesn't work on another.

### Simple Example

Without Docker:

```text
Install Python
      ↓
Install Libraries
      ↓
Configure Database
      ↓
Configure Environment
      ↓
Run Application
```

With Docker:

```text
Docker Image
     ↓
Run Container
     ↓
Application Starts
```

Docker doesn't magically solve every problem, but it makes the application environment much easier to reproduce.

---

# 4. Docker vs Virtual Machine

Both Docker and Virtual Machines are used to run applications in isolated environments.

But they work differently.

## Virtual Machine

A Virtual Machine creates a complete virtual computer.

For example:

```text
My Computer
     ↓
Virtual Machine
     ↓
Complete Operating System
     ↓
Application
```

If I create three Virtual Machines, each one may have its own operating system.

---

## Docker Container

Docker containers don't need a complete operating system for every application.

```text
My Computer
     ↓
Docker
     ↓
Container
     ↓
Application
```

Multiple containers can run on the same machine.

```text
             My Computer
                  ↓
                Docker
          ┌───────┼───────┐
          ↓       ↓       ↓
      Container Container Container
        App A      App B      App C
```

---

## Simple Comparison

| Virtual Machine | Docker Container |
|---|---|
| Has a complete guest OS | Shares the host OS kernel |
| Usually heavier | Usually lightweight |
| Uses more resources | Usually uses fewer resources |
| Usually takes longer to start | Usually starts faster |

### Easy Way to Remember

> **VM = Complete virtual computer**

> **Docker Container = Isolated environment for an application**

# 5. Benefits of Docker

Docker has several useful benefits.

### 1. Consistent Environment

The application can use the same environment wherever it runs.

### 2. Easy Deployment

We can package an application into a Docker Image and run it on another machine.

### 3. Lightweight

Containers are generally lighter than Virtual Machines.

### 4. Portable

The same Docker Image can be used in different environments.

### 5. Isolation

Different applications can run in separate containers.

For example:

```text
Container 1 → Python API

Container 2 → MySQL

Container 3 → Redis
```

### 6. Easy Scaling

If we need more copies of an application, we can create more containers.

```text
Application
    ↓
Container 1
Container 2
Container 3
Container 4
```

# 6. Basic Docker Terminology

Before learning Docker commands, we need to understand a few important words.

---

## Docker Engine

Docker Engine is the main technology that allows us to **build and run containers**.

Think of it as the part that makes Docker work on our computer.

```text
Docker Engine
      ↓
Build Images
      ↓
Run Containers
```

---

## Docker Image

A Docker Image is like a **blueprint** for a container.

It contains the things needed to create and run the application.

### Real-Life Example

Think about a house.

```text
House Blueprint
      ↓
Build House
```

Similarly:

```text
Docker Image
      ↓
Create Container
```

### Remember

> **Image = Blueprint**

---

## Docker Container

A Container is where our application actually runs.

If an Image is the blueprint:

```text
Image
  ↓
Container
  ↓
Running Application
```

### Remember

> **Container = Running instance created from an Image**

---

## Dockerfile

A Dockerfile is a file containing instructions that tell Docker **how to create an Image**.

Example:

```dockerfile
FROM python:3.12

WORKDIR /app

COPY requirements.txt .

RUN pip install -r requirements.txt

COPY . .

CMD ["python", "app.py"]
```

Don't worry if this looks confusing now.

We will learn Dockerfile properly in a later topic.

### Remember

> **Dockerfile = Instructions for building an Image**

---

## Docker Hub

Docker Hub is a place where Docker Images can be **stored and shared**.

Think of it like GitHub, but mainly for Docker Images.

```text
My Computer
     ↓
Docker Image
     ↓
Docker Hub
     ↓
Other Computer
     ↓
Docker Image
```

---

## Docker Compose

Docker Compose helps us run **multiple containers together**.

For example, a web application may need:

```text
FastAPI
   +
MySQL
   +
Redis
```

Docker Compose can help manage these containers together.

```text
        Docker Compose
              ↓
      ┌───────┼───────┐
      ↓       ↓       ↓
   FastAPI   MySQL   Redis
  Container Container Container
```

We will learn Docker Compose later.

# ❓ Interview Q&A

## Q1. What is Docker?

**Answer:**

Docker is a tool/platform used to build, package, and run applications inside containers.

---

## Q2. Why do we use Docker?

**Answer:**

We use Docker to create a consistent environment for applications and reduce dependency and configuration problems.

---

## Q3. What problem does Docker solve?

**Answer:**

Docker helps solve problems caused by different environments, dependencies, and application setups. It helps avoid the common "works on my machine" problem.

---

## Q4. What is a Docker Container?

**Answer:**

A Docker Container is an isolated environment where an application runs with its required dependencies.

---

## Q5. What is a Docker Image?

**Answer:**

A Docker Image is a blueprint or template used to create a Docker Container.

---

## Q6. What is the difference between an Image and a Container?

**Answer:**

An Image is a blueprint used to create a Container, while a Container is the environment where the application actually runs.

---

## Q7. What is a Dockerfile?

**Answer:**

A Dockerfile is a file containing instructions used to build a Docker Image.

---

## Q8. What is Docker Hub?

**Answer:**

Docker Hub is a registry where Docker Images can be stored and shared.

---

## Q9. What is Docker Compose?

**Answer:**

Docker Compose is a tool used to define and run multiple Docker containers together.

---

## Q10. What is Docker Engine?

**Answer:**

Docker Engine is the main technology that allows us to build and run Docker containers.

---

## Q11. What is the difference between Docker and a Virtual Machine?

**Answer:**

A Virtual Machine runs a complete guest operating system, while Docker containers share the host operating system's kernel and are generally more lightweight.

---

## Q12. Can multiple containers run on the same machine?

**Answer:**

Yes. Multiple containers can run on the same machine, and each container can run a different application or service.
