# 🐳 1. Docker Introduction & Basics

## 1. What is Docker?

Docker is a platform used to **build, package, and run applications inside containers**.

A Docker container contains an application along with the dependencies required to run it.

### Simple Example

```text
Application
     +
Dependencies
     ↓
   Docker
     ↓
  Container
     ↓
Running Application
```

Docker helps an application run consistently across different environments.

---

## 2. Why Docker?

A common problem in software development is:

> "It works on my machine, but it doesn't work on another machine."

This can happen because of:

- Different operating systems
- Different programming language versions
- Different library versions
- Missing dependencies
- Different configurations

Docker helps solve this problem by packaging the application and its dependencies together.

### Without Docker

```text
Developer A
     ↓
Python 3.12
Library Version A
Ubuntu
     ↓
Application Works


Developer B
     ↓
Python 3.10
Library Version B
Windows
     ↓
Application May Fail
```

### With Docker

```text
Application
     +
Dependencies
     ↓
Docker Image
     ↓
Docker Container
     ↓
Consistent Environment
```

---

## 3. Problems Docker Solves

Docker helps solve several common problems in software development.

### 1. Dependency Problems

Different computers may have different versions of libraries or packages.

### 2. Environment Problems

Development, testing, and production environments may have different configurations.

### 3. Deployment Problems

Setting up an application manually on every server can take time.

### 4. "Works on My Machine" Problem

An application may work on the developer's computer but fail on another computer.

Docker provides a consistent environment for running the application.

### Simple Flow

```text
Application
     ↓
Dependencies
     ↓
Docker
     ↓
Consistent Environment
```

## 4. Docker vs Virtual Machine

Docker containers and Virtual Machines are both used to isolate applications, but they work differently.

### Virtual Machine

A Virtual Machine runs a complete guest operating system.

```text
Physical Machine
       ↓
    Host OS
       ↓
   Hypervisor
       ↓
 Virtual Machine
       ↓
   Guest OS
       ↓
 Application
```

### Docker Container

A Docker container shares the host operating system's kernel and runs the application with its dependencies.

```text
Physical Machine
       ↓
    Host OS
       ↓
 Docker Engine
       ↓
   Container
       ↓
 Application
```

### Main Difference

```text
Virtual Machine
= Application
+ Dependencies
+ Complete Guest OS


Docker Container
= Application
+ Dependencies
```

### Comparison

| Virtual Machine | Docker Container |
|---|---|
| Includes a complete guest OS | Shares the host OS kernel |
| Generally heavier | Generally lightweight |
| Uses more resources | Usually uses fewer resources |
| Usually slower to start | Usually faster to start |
| Provides strong isolation | Provides application-level isolation |

### Easy Way to Remember

> **VM = Full OS + Application**

> **Docker = Application + Dependencies**

## 5. Benefits of Docker

### 1. Consistency

Docker provides a consistent environment for applications.

### 2. Portability

A Docker container can run on different systems that support Docker.

### 3. Lightweight

Containers generally use fewer resources than Virtual Machines.

### 4. Easy Deployment

Applications can be packaged into Docker Images and deployed easily.

### 5. Isolation

Applications can run separately inside different containers.

### 6. Scalability

Containers can be created and managed quickly when more application instances are required.

### 7. Faster Development

Developers can create the same development environment without manually installing every dependency.

## 6. Basic Docker Terminology

### Docker Engine

Docker Engine is the technology used to **build and run Docker containers**.

```text
Docker Engine
      ↓
Build Images
      ↓
Run Containers
```

---

### Docker Image

A Docker Image is a **template or blueprint used to create containers**.

```text
Docker Image
     ↓
Docker Container
```

### Remember:

> **Image = Blueprint**

---

### Docker Container

A Docker Container is an isolated environment used to **run an application**.

```text
Docker Image
     ↓
  Container
     ↓
Application
```

### Remember:

> **Container = Running instance of an Image**

---

### Dockerfile

A Dockerfile is a text file containing instructions used to **build a Docker Image**.

Example:

```dockerfile
FROM python:3.12

WORKDIR /app

COPY requirements.txt .

RUN pip install -r requirements.txt

COPY . .

CMD ["python", "app.py"]
```

We will learn Dockerfile in detail in a later topic.

---

### Docker Hub

Docker Hub is a registry where Docker Images can be **stored and shared**.

```text
Developer
    ↓
Docker Image
    ↓
Docker Hub
    ↓
Other Developer
    ↓
Docker Image
```

---

### Docker Compose

Docker Compose is a tool used to **define and run multiple containers together**.

Example:

```text
Docker Compose
      ↓
 ┌────┴─────┐
 ↓          ↓
FastAPI    MySQL
Container  Container
```

We will learn Docker Compose in detail later.

# ❓ Interview Q&A

## Q1. What is Docker?

**Answer:**

Docker is a platform used to build, package, and run applications inside containers.

---

## Q2. Why do we use Docker?

**Answer:**

We use Docker to create a consistent environment for applications and avoid dependency and configuration problems.

---

## Q3. What problem does Docker solve?

**Answer:**

Docker helps solve dependency, environment, and deployment problems, including the common "works on my machine" problem.

---

## Q4. What is a Docker Container?

**Answer:**

A Docker Container is an isolated environment used to run an application along with its dependencies.

---

## Q5. What is a Docker Image?

**Answer:**

A Docker Image is a template or blueprint used to create Docker containers.

---

## Q6. What is the difference between a Docker Image and a Container?

**Answer:**

A Docker Image is a blueprint used to create a container, while a container is a running instance created from that image.

---

## Q7. What is a Dockerfile?

**Answer:**

A Dockerfile is a text file containing instructions used to build a Docker Image.

---

## Q8. What is Docker Hub?

**Answer:**

Docker Hub is a registry used to store and share Docker Images.

---

## Q9. What is Docker Compose?

**Answer:**

Docker Compose is a tool used to define and run multiple Docker containers together.

---

## Q10. What is Docker Engine?

**Answer:**

Docker Engine is the technology that allows us to build and run Docker Images and Containers.

---

## Q11. What is the difference between Docker and a Virtual Machine?

**Answer:**

A Virtual Machine includes a complete guest operating system, while Docker containers share the host operating system's kernel and are generally more lightweight.

---

## Q12. Why are Docker containers lightweight?

**Answer:**

Containers do not need a complete guest operating system for each application. They share the host operating system's kernel, so they generally use fewer resources.

---

## Q13. Can multiple containers run on the same machine?

**Answer:**

Yes. Multiple containers can run on the same machine and can be isolated from each other.

---

# 🎯 Key Takeaways

- Docker is used to build, package, and run applications.
- Docker uses **containers** to run applications in isolated environments.
- A **Docker Image** is a blueprint.
- A **Docker Container** is a running instance of an Image.
- A **Dockerfile** contains instructions for building an Image.
- Docker helps solve dependency and environment problems.
- Docker containers are generally lightweight compared with Virtual Machines.
- **Docker Hub** is used to store and share Images.
- **Docker Compose** is used to run multiple containers together.
- **Docker Engine** is used to build and run containers.
